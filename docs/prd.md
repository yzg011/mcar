# 需求文档

## 1. 应用概述

### 1.1 应用名称
智能挪车系统

### 1.2 应用描述
一个基于Web的智能挪车通知系统，帮助被堵车辆车主快速联系挡路车辆车主。系统通过实时通信技术实现通知推送，支持位置共享和快捷留言，提供被堵车方和车主两种角色视图。

## 2. 用户与使用场景

### 2.1 目标用户
- 被堵车方：车辆被其他车辆挡住无法移动的车主
- 车主：接收挪车请求的车辆所有者

### 2.2 核心使用场景
- 被堵车方发现车辆被挡，通过系统发送挪车请求
- 车主通过分享链接或房间码接收实时挪车通知
- 车主确认收到请求并前往挪车

## 3. 页面结构与功能说明

### 3.1 页面结构

```
智能挪车系统
├── 呼叫车主挪车页面（被堵车方）
├── 收到挪车请求页面（车主端）
└── 已发送通知确认页
```

### 3.2 呼叫车主挪车页面

#### 3.2.1 页面布局
- 顶部：车辆图标 + 标题「呼叫车主挪车 / Notify Car Owner」
- 留言输入框：用户可输入留言内容（可选）
- 快捷标签区域：包含「挡路」「临停」「没接」「加急」四个标签按钮
- 我的位置卡片：显示定位状态（已获取位置✓）
- 底部：蓝色按钮「一键通知车主」

#### 3.2.2 功能说明
- 留言输入：用户可自由输入留言内容，留言内容随通知一起发送
- 快捷标签选择：点击标签按钮可选中对应标签，支持多选
- 位置获取：调用浏览器geolocation API自动获取当前位置，获取成功后在位置卡片显示「已获取位置✓」
- 发送通知：点击「一键通知车主」按钮后，通过Supabase Realtime发送通知，跳转到已发送通知确认页

### 3.3 收到挪车请求页面

#### 3.3.1 页面布局
- 顶部：挥手emoji图标
- 标题：「收到挪车请求」
- 副标题：「对方正在等待，请尽快确认」
- 对方位置卡片：包含高德地图和Apple Maps两个导航按钮
- 底部：绿色按钮「我已知晓，正在前往」

#### 3.3.2 功能说明
- 实时接收通知：通过Supabase Realtime实时接收被堵车方发送的挪车请求
- 显示留言内容：展示被堵车方输入的留言和选中的快捷标签
- 导航跳转：点击高德地图或Apple Maps按钮，跳转到对应导航应用并传入对方位置坐标
- 确认响应：点击「我已知晓，正在前往」按钮后显示确认状态

### 3.4 已发送通知确认页

#### 3.4.1 功能说明
- 显示通知已发送的确认信息
- 提示车主正在接收通知

## 4. 业务规则与逻辑

### 4.1 房间机制
- 被堵车方发送通知时生成唯一房间码
- 通过分享链接或房间码让车主打开车主端界面
- 车主通过链接或房间码进入对应房间接收通知

### 4.2 角色切换
- 系统支持两种角色：请求者（被堵车方）和车主（接收通知方）
- 用户通过不同入口访问对应角色界面

### 4.3 实时通信流程
- 被堵车方点击「一键通知车主」后，通过Supabase Realtime发送通知
- 车主端实时监听房间消息，收到通知后自动刷新页面显示挪车请求
- 通知内容包含：留言内容、快捷标签、对方位置坐标

### 4.4 位置获取规则
- 调用浏览器geolocation API获取当前位置
- 位置获取成功后在位置卡片显示「已获取位置✓」
- 位置坐标随通知一起发送给车主

## 5. 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 位置获取失败 | 提示用户授权位置权限或手动输入位置 |
| 网络连接中断 | 提示网络异常，通知发送失败 |
| 车主未打开链接 | 被堵车方显示等待状态 |
| 房间码无效 | 提示房间不存在或已过期 |
| 快捷标签未选择 | 允许不选择标签直接发送通知 |
| 留言内容为空 | 允许不填写留言直接发送通知 |

## 6. 验收标准

1. 被堵车方打开呼叫车主挪车页面，系统自动获取当前位置并显示「已获取位置✓」
2. 被堵车方输入留言内容或选择快捷标签（挡路/临停/没接/加急）
3. 被堵车方点击「一键通知车主」按钮，系统生成房间码并跳转到已发送通知确认页
4. 车主通过分享链接或房间码打开收到挪车请求页面，实时接收到通知内容（包含留言、标签、位置）
5. 车主点击高德地图或Apple Maps按钮，成功跳转到导航应用并传入对方位置坐标
6. 车主点击「我已知晓，正在前往」按钮，系统显示确认状态
